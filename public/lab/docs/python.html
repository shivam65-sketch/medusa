The Python tab

A small Python editor for the ideas that don’t fit a form: explore a data file, test a rule you just thought of, compare settings, or chart anything, on your own downloaded files and with the same engine as the Dashboard.

How it works

  1. Attach data: tick files on the right (your Downloads and Uploads folders), or add a CSV/ZIP from this computer (used for this session only, not stored). Each gets a name such as BTCUSDT-futures-1h. Ticking a file puts the line that loads it at the top of your code, with what’s in the file; unticking it takes that line out again (if you haven’t changed it). Insert does the same for a file, ticking it if needed.
  2. Write code, or start from an example (the Examples menu). The editor colours the code, marks mistakes as you type and suggests names (see below). Tab indents; Enter keeps the indentation. The code is kept in this browser as you type; Save as .py downloads it and Open loads a .py file.
  3. Run (or Ctrl+Enter). The output, any error with its line number, and your matplotlib charts appear under the code. Stop ends a run that takes too long.

Ticking a file adds two lines like these at the top:

# ── BTCUSDT-futures-4h: BTCUSDT futures 4h · 10,956 candles · 2021-10-13 → 2026-10-12
data = load("BTCUSDT-futures-4h")    # .t .o .h .l .c .v numpy arrays, .df() pandas; help(data) lists everything

The variable is data, or a name made from the file (ethusdt_1h) when your code already uses data. Tick a second file and its lines go under the first.

The editor

  • Colours: keywords, text in quotes, numbers, comments, Python’s own functions, and MEDUSA’s names (load, backtest …) each have their own colour, so a missing quote or bracket shows at once.
  • Mistakes as you type: a red wavy line marks an error (a bracket never closed, a missing :, a wrong indent, a quote that never ends, = where == was meant …) and the message shows at the end of the line; the line number turns red. A yellow line is a warning: a name a data file doesn’t have (data.close instead of data.c), load("name") of a file that isn’t ticked, or load() with several files ticked. The list under the editor shows every problem; click one to jump to it.
  • Python’s own check: a quick check runs on every key. Once Python has started (it starts in the background when you begin typing), Python’s compiler checks the code too, a moment after you stop; then the list says checked by Python, and its message is exactly the one Run would give. Nothing runs during the check.
  • Suggestions: type data. to see what a data file has, r. after r = backtest(…) for a result, np., pd. or plt. for the libraries, or the start of any name; Ctrl+Space asks at any point. ↑ ↓ choose, Enter or Tab puts it in, Esc closes. The box under the list says what the selected name is.
  • Hints: while you type the brackets of load(, backtest( or an indicator such as ema(, a hint shows what goes in them.

load(): your data file in Python

load() hands your code one of the ticked data files as a Data object: the candles as numpy arrays (one value per candle, oldest first), plus a few facts about the file. When you press Run, MEDUSA reads each ticked file (from its storage, or from this browser for a file added from this computer) and gives Python a fresh copy for that run.

Names are SYMBOL-market-timeframe, e.g. ETHUSDT-spot-1d. Two files with the same name (say two downloads of BTCUSDT 1h over different dates) become BTCUSDT-futures-1h and BTCUSDT-futures-1h-2. A file added from this computer is named from its file name; when that doesn’t say the coin it is FILE-…, and when MEDUSA can’t tell the timeframe from the gaps between candles it ends in -custom (and is treated as 1h in backtests).

Rows, times and gaps

  • Row i is one candle in every array: data.t[i], data.o[i] … data.c[i]. Rows are sorted by time with duplicates dropped, and a download keeps only finished candles.
  • Times are UTC milliseconds. local_time(data.t) turns them into numpy dates in your time zone, for printing, charts and picking dates (see the recipes). To get a Python datetime: from datetime import datetime, timezone, then datetime.fromtimestamp(data.t[i] / 1000, timezone.utc).
  • Missing candles are not filled in. If the exchange was down, the time simply jumps; the recipe below finds such gaps. Prices are as Binance gives them: no adjustments.

data.df(): the pandas view

Columns open high low close volume, plus taker_buy_volume when the file has it; the index is the open time in your time zone, named time. pandas loads by itself when your code calls .df(). Each call makes a new table, so keep it in a variable: df = data.df(). Funding isn’t in the table; add it like this:

import pandas as pd
df = data.df()
if data.funding_r is not None:
    f = pd.Series(data.funding_r, index=pd.to_datetime(data.funding_t, unit="ms", utc=True).tz_convert(df.index.tz))
    df["funding"] = f.reindex(df.index, method="ffill")    # the last rate known at each candle

Recipes

data = load()

# the last candle, in your time zone
print(local_time(data.t[-1]), "close", data.c[-1])

# only 2024 (your time zone): a True/False mask for every candle
lt = local_time(data.t)
in_2024 = (lt >= np.datetime64("2024-01-01")) & (lt < np.datetime64("2025-01-01"))
c = data.c[in_2024]
print(f"2024: {len(c):,} candles, from {c[0]:,.2f} to {c[-1]:,.2f} ({(c[-1] / c[0] - 1) * 100:+.1f}%)")

# the first candle on or after a date
i = np.searchsorted(lt, np.datetime64("2024-06-01"))
print("June 2024 starts at row", i)

# moves from close to close, and the candle's own range
ret = data.c[1:] / data.c[:-1] - 1
rng = (data.h - data.l) / data.o
print(f"average move {ret.mean() * 100:+.4f}%, average range {rng.mean() * 100:.2f}%")

# gaps: places where the time jumps by more than one candle
step = np.median(np.diff(data.t))
gaps = np.nonzero(np.diff(data.t) > step)[0]
print(len(gaps), "gaps")
for k in gaps[:5]:
    print("  ", local_time(data.t[k]), "→", local_time(data.t[k + 1]))
# funding: what a long position paid each year (a negative number means it was paid)
data = load()
if data.funding_r is not None:
    years = local_time(data.funding_t).astype("datetime64[Y]")
    for y in np.unique(years):
        print(y, f"{data.funding_r[years == y].sum() * 100:+.2f}%")

# daily candles from 1-hour ones (days in your time zone)
daily = data.df().resample("1D").agg({"open": "first", "high": "max", "low": "min", "close": "last", "volume": "sum"}).dropna()
print(daily.tail())
# two files side by side, on the candles both have (tick both first)
btc, eth = load("BTCUSDT-futures-1h"), load("ETHUSDT-futures-1h")
t, ib, ie = np.intersect1d(btc.t, eth.t, return_indices=True)
ratio = eth.c[ie] / btc.c[ib]
print(f"ETH/BTC went from {ratio[0]:.5f} to {ratio[-1]:.5f}")

# every ticked file
for name in files():
    d = load(name)
    print(f"{name}: {len(d):,} candles, last close {d.c[-1]:,.2f}")

Good to know

  • Your copy: the arrays belong to this run. Changing them never changes the stored file, and the next run starts from the file again. Within one run, load("x") twice gives the same object, so use data.c.copy() before changing values you still need.
  • Size: each column is 8 bytes per candle; a million candles is about 60 MB in Python. Very large files take a few seconds to load before your code starts.
  • In a strategy: prepare(self, d) gets a similar object from the engine (d.t d.o d.h d.l d.c d.v, d.interval, d.symbol), not the Data object itself; see .

Libraries load only when you use them

Python runs in a background thread with only the libraries your code imports. The first time, the browser downloads them from MEDUSA (pandas about 5 MB, matplotlib about 10 MB with its helpers, scipy 14 MB, statsmodels 8 MB) and keeps them, so later starts take a second or two. The thread starts when you begin typing (so the editor can use Python’s check and Run starts at once), and again when your code needs a library it doesn’t have yet. Code that imports nothing extra stays as light as the rest of the Lab. Other libraries (seaborn, scikit-learn, TA-Lib …) are not available; MEDUSA’s indicators covers the common indicators.

Safety

Your code runs in a background thread of this page whose network access is switched off before your code starts: it can read the files you attached and calculate, but it can’t send anything anywhere, or reach your account or other files. Code you paste from elsewhere can’t leak your data.

Charts

Use matplotlib as usual: import matplotlib.pyplot as plt, draw, then plt.show(). Every chart shown, and any still open at the end, appears under the output. Charts are drawn at twice the size they’re shown at: Open in new tab shows one full size in its own browser tab (zoom in there), and Save PNG downloads it. For a bigger chart to begin with, ask for one: plt.figure(figsize=(14, 6)).

Taking a backtest to another computer

Every backtest report (from the Dashboard or from .save() here) has a Python code button. It gives one standalone .py file: MEDUSA’s engine, indicators and statistics, the strategy’s code, and the exact settings of that run, including the warm-up and your time zone. On any computer with Python 3 and numpy:

pip install numpy
python medusa_turtle_BTCUSDT_4h.py              # downloads the same candles (and funding) from Binance
python medusa_turtle_BTCUSDT_4h.py --csv my.csv # or uses a file (MEDUSA's CSV/ZIP export, or a Binance archive)
python medusa_turtle_BTCUSDT_4h.py --trades trades.csv --json report.json

A test on a file you uploaded needs that file with --csv. The script prints the same report and compares its numbers with the ones MEDUSA got (they match to the cent when the data is the same). Nothing in it talks to MEDUSA, and you can read and change every line.

Examples

data = load()
r = backtest("ichimoku", data, notional_pct=25, sizing="notional", start="2023-01-01")
r.report()

The trap: with a few lines of code you can try hundreds of settings, and the best of them will always look great on past data. Choose settings on one part of the data (the split setting divides the report), then look at the rest once. The “Compare settings” example shows how.
